# 완료 기준과 검증 근거

이 문서는 로컬 해커톤 프로토타입의 완료 기준을 실제 코드와 실행 기록에 연결합니다. 실제 ChatGPT 호출, 외부 업무 시스템, 운영 인증과 공개 배포는 포함하지 않습니다. 자동 AI 개발을 수행했다고 해석하면 안 됩니다.

## 핵심 흐름

최신 압축을 새 폴더에 풀고 의존성을 새로 설치한 빌드 서버에서, 아래 흐름의 **프로젝트 변경을 모두 UI로 수행**했습니다. 김지민·이서연은 한 Chrome 브라우저에서 프로필을 전환했습니다. JSON 준비와 서버 상태 확인에는 별도 로컬 API 세션의 읽기를 사용했습니다.

| 완료 기준 | 구현된 동작 | 직접 확인한 근거 |
| --- | --- | --- |
| 팀 프로젝트 생성 | 문제·목표를 입력하고 로컬 DB에 저장 | 새 설치 UI 생성, `submission-refresh-ui-browser.json`, 최종 프로젝트 v22 |
| 여러 사용자 참여 | 초대 코드로 참여, 멤버별 대화와 PRD 동의 | 두 프로필 UI 참여·작성·동의. 독립 API 세션 접근 검사 `api-flow.mjs` |
| 대화에서 공동 요구사항 작성 | 개인 대화, 수동 AI 응답 반입, 원문 연결 요구사항, 공동 PRD와 전원 동의 | 두 대화·요구사항2개·PRD v1 동의2명. 합성 응답에 실제 ChatGPT 호출 없음 표시 |
| 작고 검증 가능한 스토리 분할 | 설계 JSON 검토·백로그 등록, 완료 조건·테스트·담당·의존성, 개발 준비 | UI 설계2개 반입, 각 기준1개. `submission-refresh-ui-plan.json` |
| 스토리 병렬 개발 | 독립 스토리를 함께 시작하고 개별 고정 요청·결과를 관리 | UI 동시 시작2개, HTML/JS와 CSS 결과 각각 반입. `submission-refresh-ui-running.json` |
| 결과 통합 | 시작 기준과 현재 코드 비교, 충돌 검토, 새 릴리스 생성 | UI 결과2개·파일3개 통합. 충돌 분기는 `integration-baseline.mjs`, `artifact-removal.mjs`와 기존 실제 UI 기록 |
| 테스트 환경 실행 | 격리 iframe에서 정적 결과 실행, 기준별 기록, 근거가 있을 때 완료 | 실제 확인→초기화→확인, 32px 상태 글자와 구분된 버튼. 기준2개 기록 후 완료2개 |
| 피드백 개선 | 릴리스별 피드백, 수정·종결·재열기, 후속 스토리 연결·복원 | `feedback-lifecycle.mjs`, 기존 `feedback-browser-result.json` |

핵심 흐름의 최신 근거는 [제출본 검증](../evidence/submission-refresh-validation.json), [UI 관찰](../evidence/submission-refresh-ui-browser.json), [최종 서버 상태](../evidence/submission-refresh-ui-final-project.json), [실제 실행 화면](../evidence/screenshots/submission-refresh-ui-preview.png)입니다.

마지막 독립 실행 검사에서 이전 비품 신청 앱의 수정 시작이 원본을 지우고 수량을1로 바꾸는 결함을 발견했습니다. 앞선 기본 동작 검사가 이 경계를 검증하지 못했음을 기록하고, 새 **비품 신청 · 수정과 취소를 보존하는 시연**으로 보완했습니다. 원본·수량 유지, 수정 취소, 오류 입력 보존, 여러 신청의 대상 구분,390px 화면까지 [실제 브라우저 관찰](../evidence/safe-edit-browser-result.json)과 [플랫폼 기록](../evidence/safe-edit-platform-result.json)으로 확인했습니다. 완료2개·검증 기준5개인 최종 v24와 코드 대조는 [최신 시연 검증](../evidence/safe-edit-validation.json)에 있습니다. 이전 자료는 삭제하지 않았습니다.

## 수정·취소·휴지통·복원

| 대상 | 지원 범위와 데이터 보존 | 검증 |
| --- | --- | --- |
| 프로필·프로젝트·팀 | 생성·수정·휴지통·복원, 참여·나가기·제외·오너 이전·초대 코드 재발급 | `profile-lifecycle.mjs`, `api-flow.mjs`, `api-guards.mjs`, 기존 프로젝트 찾기 UI 기록 |
| 대화·메시지 | 제목·원문 수정, 휴지통·복원, 이전 원문 이력과 새 버전 복원 | `message-provenance.mjs`, `api-guards.mjs`, 기존 원문 이력 UI 기록 |
| 요구사항·PRD | 수정·합의·충돌·통합·원문 연결, 요구사항 휴지통·복원, PRD 버전·이전 본문 복원·동의 철회 | `requirement-*.mjs`, `prd-*.mjs`, 각각의 실제 UI 기록 |
| 스토리·개발 작업 | 스토리 수정·담당 변경·휴지통·복원, 작업 취소와 취소 작업 보관·복원, 제출 결과 수정·이력 | `story-*.mjs`, `run-submissions.mjs`, `run-result-context.mjs`, 담당 인계 UI 기록 |
| 릴리스·테스트·피드백 | 릴리스 이름·활성 버전 변경과 비활성 버전 보관, 테스트 수정·휴지통·복원, 피드백 전체 수명주기 | `integration-baseline.mjs`, `test-*.mjs`, `feedback-lifecycle.mjs` 및 실제 UI 기록 |

사용자가 편집하는 현재 자료와 과거 근거를 구분합니다. 활동 이력과 과거 버전은 읽기 전용입니다. 진행 중 작업이나 통합 이력에 연결된 항목을 임의로 없애지 않도록 취소·연결 해제·릴리스 전환 등의 조건을 검사합니다. 휴지통은 복원 가능하며 기존 자료를 물리 삭제하지 않습니다. 오래된 제출이나 과거 테스트로 새 버전의 완료를 주장할 수 없습니다.

실제 수동 전달의 복사 동작도 확인했습니다. 두 개발 작업의 복사 버튼을 누른 직후 클립보드를 읽어 서버에 고정된 각 요청과 전체 문자열이 일치하고 작업·스토리 문맥이 구분되는 것을 확인했습니다(`evidence/handoff-clipboard-result.json`). 외부 ChatGPT에 붙여넣거나 전송하지 않았고, 클립보드 접근 거부 상황은 검사하지 않았습니다.

## 실행·제출 기준

- 최신 코드 타입 검사, 개발 서버 대상 전체 회귀 검사, 빌드가 통과했습니다. `workspace-refresh-validation.json`에 명령 세션과 소스 해시가 있습니다.
- 최신 압축627파일의 무결성 확인 후, 같은 macOS/Node24.16 환경에서 기존 node_modules를 복사하지 않고 npm 캐시만으로673패키지를 설치했습니다. 마이그레이션2개·타입 검사·빌드가 통과했습니다.
- 새 빌드 서버 대상 첫 회귀 검사에서는 로컬 Wrangler가 요청 중 재시작해503을 반환했습니다. 실패를 보존했고, 같은 서버에서 다시 실행한 전체 검사는 통과했습니다. POST 자동 재시도나 테스트 기대값 완화는 하지 않았습니다.
- 실제 UI 흐름을 마친 뒤 서버를 명시적으로 종료·재시작했습니다. 전체 프로젝트 v22가 동일했고 완료2개·검증 기록1개와 코드 재실행을 확인했습니다.
- 합성 샘플은 `lib/teamvibe/seed.ts`, `data/`에, 최신 권장 실행 코드와 화면은 `data/demo-safe-edit/`, `evidence/safe-edit-preview.html`, `evidence/screenshots/final-overview.png`, `safe-edit-mobile.png`에 있습니다. 이전 `demo-*` 자료는 과거 검증 자료입니다.
- 새 시연 코드와 준비 스크립트는 실제 브라우저 실행과 구문 검사를 통과했습니다. 플랫폼의 기존163파일은 새 설치·전체 회귀·빌드 검증본과 같으며 새 시연 이후 플랫폼 코드를 바꾸지 않았습니다. 최종 압축에서는 두 소스 묶음을 각각 대조합니다.
- 실행 방법과 한계는 [처음 실행하기](START_HERE.md)와 [README](../README.md)에 있습니다. 테스트의 데이터 연결 검사와 실제 브라우저 코드 실행을 구분합니다.
- 실제 Codex 세션은 `evidence/agent-sessions/manifest.json`의 시점까지 복사·해시 보존합니다. 앱 활동 기록이나 합성 AI 수행 로그를 실제 에이전트 로그로 대신하지 않습니다.
- 최종 제출 압축의 경로·크기·해시는 작업 폴더의 `outputs/latest-submission.json`에 기록합니다. 그 압축의 runtime 소스는 새 설치 검증본과 해시로 비교합니다. 이후 문서·증거·세션 스냅샷 추가는 기능 검증과 구분합니다.

## 확인하지 않은 범위

캐시 없는 설치, 다른 운영체제·컴퓨터, 여러 브라우저의 동시 UI 사용자, 실제 ChatGPT 서비스 호출, 임의 생성 코드의 정확성·보안, 대규모 부하와 장기 운영은 검증하지 않았습니다. 페이지 메모리의 미전송 초안은 새로고침·탭 종료 후 복구되지 않습니다. 로컬 시연 프로필은 운영 인증이 아니며 같은 브라우저 탭은 쿠키를 공유합니다. 정적 HTML/CSS/classic JS 실행만 지원하고 별도 서버 프로그램이나 외부 데이터베이스를 실행하지 않습니다.
